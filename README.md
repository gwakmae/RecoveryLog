# 회복 기록 — RecoveryLog

배달 오전·오후 수익을 중심으로 손실 회복을 기록하는 독립 프로젝트입니다.

기존 MinusWrite 프로젝트의 파일과 데이터는 수정하지 않습니다.

## 파일 구성

- css/style.css: 전체 화면 스타일
- index.html: 앱 시작 페이지
- js/app.js: 화면과 이벤트 처리
- js/calc.js: 금액, 날짜, 누계, 예상 시나리오 계산
- js/data.js: 브라우저 저장, 백업 검증, 선택적 GitHub 동기화
- js/tradeImport.js: 외부 AI용 프롬프트와 거래 JSON 검증
- tests/calc.test.html: 계산 테스트 페이지

## 실행

VS Code의 Live Server 등 정적 웹 서버로 index.html을 여세요.

GitHub Pages에도 배포할 수 있습니다.
빌드 과정이나 외부 JavaScript 라이브러리는 필요하지 않습니다.

테스트는 같은 서버에서 tests/calc.test.html을 열어 실행합니다.

## 시작하기

1. 설정에서 시작 손실금액을 원화로 저장합니다.
2. 오늘 배달에서 오전·오후 수익을 입력합니다.
3. 회복 계획에서 오전·오후 목표와 배달 요일을 선택합니다.
4. 트레이딩을 했다면 별도 화면에 기록합니다.

시작 손실을 설정하기 전에도 배달과 트레이딩 기록은 저장할 수 있습니다.
남은 손실과 시나리오는 시작 손실을 설정한 뒤 표시됩니다.

## 계산 기준

통합 회복액:
배달 수익 + 트레이딩 원화 순손익 + 리베이트 원화 금액

남은 손실:
시작 손실 - 통합 회복액

회복액은 실제 상환액이나 별도 계좌 잔액이 아닙니다.
이 앱에서 기록한 수입·손익 기준의 회복 실적입니다.

기름값과 생활비는 차감하지 않습니다.

배달의 빈칸은 미입력, 0원은 명시적으로 입력한 무수입입니다.
하루에 오전·오후 중 하나만 입력해도 저장할 수 있습니다.

## 트레이딩과 환율

포지션 손익과 리베이트는 USD로 입력합니다.
손익은 소수 둘째 자리까지 입력합니다.

각 날짜의 적용 환율을 함께 저장합니다.
저장된 과거 기록은 현재 환율로 자동 재계산하지 않습니다.

일별 포지션 손익 합계와 일별 리베이트를 각각 원 단위로 반올림한 뒤 더합니다.
따라서 표시되는 트레이딩 원화 금액과 리베이트 원화 금액의 합이 통합 계산과 일치합니다.

환율 조회 버튼은 open.er-api.com의 USD 기준 KRW 값을 가져옵니다.
이는 거래일 환율을 보증하지 않는 조회값입니다.
특히 과거 날짜에는 해당 날짜에 사용할 환율을 직접 확인해 입력하세요.

조회 실패 시 임의 환율을 사용하지 않습니다.

## 회복 계획

기본 비교 금액:
- 하루 30,000원
- 하루 35,000원
- 하루 40,000원
- 하루 60,000원: 높은 수입 참고용
- 직접 설정한 오전·오후 목표
- 실제 배달 기록일 평균: 기록이 있을 때 표시

계획은 선택한 배달 요일에만 수입이 발생한다고 가정합니다.
공휴일, 날씨, 휴무, 수입 변동은 자동으로 예측하지 않습니다.

계획 시작일은 최소 내일입니다.
저장된 시작일이 과거가 되면 계산 시 내일로 이동합니다.
선택한 시작일이 배달 요일이 아니면 다음 배달 요일부터 계산합니다.

실제 기록일 평균에는 0원으로 기록한 날을 포함합니다.
아직 입력하지 않은 날은 포함하지 않습니다.
평균의 원 미만은 버립니다.

목표 완료일 역산은 시작일과 완료일을 모두 포함한 배달 가능 일수로 계산합니다.
필요한 하루 수입은 원 단위 올림입니다.

미래 트레이딩 수익은 예상 계획에 넣지 않습니다.
실제로 저장한 트레이딩 손익만 남은 손실에 반영합니다.

## 브라우저 저장

전체 데이터 저장 키:
recovery_log_v1

GitHub 연결 정보 저장 키:
recovery_log_github_v1

GitHub 토큰:
sessionStorage의 recovery_log_github_token_v1

기존 MinusWrite 저장 키를 사용하지 않습니다.

브라우저 데이터 삭제, 시크릿 모드 종료, 기기 변경으로 로컬 데이터가 사라질 수 있습니다.
JSON 백업을 주기적으로 내려받으세요.

다른 탭에서 데이터가 변경된 경우 이전 탭의 저장은 거부합니다.
먼저 현재 화면의 입력을 별도로 보관하고 새로고침하세요.

## JSON 백업

설정에서 JSON 파일을 다운로드하거나 복원할 수 있습니다.

복원은 현재 데이터를 교체합니다.
앱의 프로젝트 식별자와 스키마가 일치하는 파일만 허용합니다.
기존 MinusWrite JSON은 가져오지 않습니다.

백업 파일에는 GitHub 토큰이 포함되지 않습니다.

## 선택적 GitHub 수동 동기화

원격 파일 경로:
data/recovery-log.json

기존 data/recovery-entries.json과 분리되어 있습니다.

1. 새 저장소를 만들고 최소 한 번 커밋합니다.
2. 설정에서 소유자, 저장소, 브랜치를 저장합니다.
3. 필요한 경우 해당 저장소의 Contents 읽기/쓰기 권한 토큰을 입력합니다.
4. 기존 원격 파일이 있으면 먼저 원격 불러오기를 실행합니다.
5. 로컬 기록 후 원격 업로드를 실행합니다.

공개 저장소의 데이터는 다른 사람에게 공개될 수 있습니다.
공개를 원하지 않으면 저장소와 호스팅 방식을 별도로 검토하세요.

토큰은 현재 탭의 세션에만 보관하며 JSON 백업에 넣지 않습니다.
공용 기기에서는 사용하지 마세요.

자동 동기화나 기기별 변경 자동 병합은 하지 않습니다.
원격 파일이 마지막으로 확인한 버전과 다르면 업로드를 거부합니다.

충돌한 경우:
1. 로컬 JSON 백업을 먼저 다운로드합니다.
2. 원격 데이터를 확인합니다.
3. 필요한 기록을 정리한 뒤 다시 저장합니다.

원격 불러오기는 현재 로컬 데이터를 교체하므로 백업 후 실행하세요.

## AI 거래 가져오기

트레이딩 화면에서 프롬프트를 복사합니다.
외부 AI에 프롬프트와 거래 화면을 전달하고 반환된 JSON을 붙여넣습니다.

앱이 AI 서비스를 직접 호출하지 않으며 AI API 키도 요구하지 않습니다.
날짜, USD 통화, 랏수, 손익, 거래번호 중복을 검증합니다.

검토 후 입력표에 추가해도 아직 저장된 것은 아닙니다.
거래 내용을 직접 확인하고 트레이딩 저장을 눌러야 합니다.

AI가 거래 손익을 잘못 읽을 수 있으므로 원본과 반드시 대조하세요.

## 검증 범위

계산 테스트 페이지에 다음 항목을 포함합니다.

- 배달 0원과 미입력 구분
- 트레이딩 손실과 리베이트 환산
- 주당 배달 요일 반영
- 시작일 및 완료일 포함 계산
- 목표 완료일 역산
- 남은 손실이 0인 경우
- 실제 평균의 0원 기록 포함

테스트 페이지는 브라우저에서 실행해야 합니다.
