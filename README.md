# 회복 기록 — RecoveryLog

쿠팡·배민 상세 수입 또는 배달 합산 수입과 그 외 수입을 기록하는 회복 프로젝트입니다.

기존 MinusWrite 프로젝트의 파일과 데이터는 수정하지 않습니다.

## 파일 구성

- css/style.css: 전체 화면 스타일
- index.html: 앱 시작 페이지
- js/app.js: 화면과 이벤트 처리
- js/calc.js: 금액, 날짜, 누계, 예상 시나리오 계산
- js/data.js: 브라우저 우선 저장, 미동기 변경분 보존, GitHub 자동 동기화, 백업 검증
- js/tradeImport.js: 외부 AI용 프롬프트와 거래 JSON 검증
- tests/calc.test.html: 계산 테스트 페이지

## 실행

VS Code의 Live Server 등 정적 웹 서버로 index.html을 여세요.

GitHub Pages에도 배포할 수 있습니다.
빌드 과정이나 외부 JavaScript 라이브러리는 필요하지 않습니다.

테스트는 같은 서버에서 tests/calc.test.html을 열어 실행합니다.

## 시작하기

1. 설정에서 시작 손실금액을 원화로 저장합니다.
2. 오늘 수입에서 상세 입력 또는 합산 입력을 선택합니다.
3. 상세 입력이면 쿠팡·배민 수입을, 합산 입력이면 배달 합계만 입력합니다.
4. 다른 일을 해서 번 돈은 그 외 수입에 입력합니다.
5. 회복 계획에서 하루 배달 목표를 설정합니다. 배달은 주 7일 기준입니다.
6. 트레이딩을 했다면 별도 화면에 기록합니다.

시작 손실을 설정하기 전에도 배달과 트레이딩 기록은 저장할 수 있습니다.
남은 손실과 시나리오는 시작 손실을 설정한 뒤 표시됩니다.

## 계산 기준

통합 회복액:
배달 수익 + 그 외 수입 + 트레이딩 원화 순손익 + 리베이트 원화 금액

남은 손실:
시작 손실 - 통합 회복액

회복액은 실제 상환액이나 별도 계좌 잔액이 아닙니다.
이 앱에서 기록한 수입·손익 기준의 회복 실적입니다.

기름값과 생활비는 차감하지 않습니다.

상세 입력은 쿠팡·배민 수입을 더합니다.
합산 입력은 배달 합계 한 칸만 사용합니다.
두 방식은 동시에 계산하지 않습니다.
입력 방식을 바꿀 때 기존 금액을 자동으로 옮기지는 않으며, 현재 선택한 방식만 저장합니다.

빈칸은 미입력, 0원은 명시적으로 입력한 무수입입니다.
상세 입력에서는 쿠팡·배민 중 하나만 입력해도 됩니다.
배달 없이 그 외 수입만 저장할 수도 있습니다.

그 외 수입은 전체 회복액에 포함하지만 배달 수익이나 배달 평균에는 포함하지 않습니다.
기존 오전·오후 기록은 합계를 보존해 합산 입력 기록으로 불러옵니다.

## 트레이딩과 환율

포지션 손익과 리베이트는 USD로 입력합니다.
손익은 소수 둘째 자리까지 입력합니다.

각 날짜의 적용 환율을 함께 저장합니다.
저장된 과거 기록은 현재 환율로 자동 재계산하지 않습니다.

일별 포지션 손익 합계와 일별 리베이트를 각각 원 단위로 반올림한 뒤 더합니다.
따라서 표시되는 트레이딩 원화 금액과 리베이트 원화 금액의 합이 통합 계산과 일치합니다.

환율 조회 버튼은 open.er-api.com의 USD 기준 KRW 값을 가져옵니다.
이는 거래일 환율을 보증하지 않는 조회값입니다.
특히 과거 날짜에는 해당 날짜에 사용할 환율을 직접 확인해 입력하세요.

조회 실패 시 임의 환율을 사용하지 않습니다.

## 회복 계획

기본 비교 금액:
- 하루 30,000원
- 하루 35,000원
- 하루 40,000원
- 하루 60,000원: 높은 수입 참고용
- 직접 설정한 오전·오후 목표
- 실제 배달 기록일 평균: 기록이 있을 때 표시

배달은 주 7일 기준으로 계산합니다.
공휴일, 날씨, 휴무, 수입 변동은 자동으로 예측하지 않습니다.

계획 시작일은 최소 내일입니다.
저장된 시작일이 과거가 되면 계산 시 내일로 이동합니다.

실제 배달 기록일 평균에는 배달을 0원으로 기록한 날을 포함합니다.
배달 미입력일과 그 외 수입만 기록한 날은 포함하지 않습니다.
평균의 원 미만은 버립니다.

목표 완료일 역산은 시작일과 완료일을 모두 포함한 배달 가능 일수로 계산합니다.
필요한 하루 수입은 원 단위 올림입니다.

미래 트레이딩 수익은 예상 계획에 넣지 않습니다.
실제로 저장한 트레이딩 손익만 남은 손실에 반영합니다.

## 브라우저 저장

전체 데이터와 미동기 변경분 저장 키:
recovery_log_v1

수입·트레이딩·설정·목표를 저장하면 브라우저에 먼저 기록하고 GitHub 동기화를 시도합니다.
통신 실패나 토큰 미설정 시에도 로컬 변경분을 유지합니다.
앱을 다시 열거나 동기화 재시도를 누르면 다시 시도합니다.

JSON 백업에는 사용자 데이터만 포함하고 내부 동기화 정보는 포함하지 않습니다.

GitHub 연결 정보 저장 키:
recovery_log_github_v1

GitHub 토큰:
sessionStorage의 recovery_log_github_token_v1

기존 MinusWrite 저장 키를 사용하지 않습니다.

브라우저 데이터 삭제, 시크릿 모드 종료, 기기 변경으로 로컬 데이터가 사라질 수 있습니다.
JSON 백업을 주기적으로 내려받으세요.

다른 탭에서 데이터가 변경된 경우 이전 탭의 저장은 거부합니다.
먼저 현재 화면의 입력을 별도로 보관하고 새로고침하세요.

## JSON 백업

설정에서 JSON 파일을 다운로드하거나 복원할 수 있습니다.

복원은 현재 데이터를 교체합니다.
앱의 프로젝트 식별자와 스키마가 일치하는 파일만 허용합니다.
기존 MinusWrite JSON은 가져오지 않습니다.

백업 파일에는 GitHub 토큰이 포함되지 않습니다.

## GitHub 자동 동기화

원격 파일 경로:
data/recovery-log.json

기존 data/recovery-entries.json과 분리되어 있습니다.

최초 설정:
1. 새 저장소를 만들고 최소 한 번 커밋합니다.
2. 앱 설정에서 소유자, 저장소, 브랜치를 저장합니다.
3. 해당 저장소의 Contents 읽기·쓰기 권한 토큰을 저장합니다.

GitHub Pages 주소에서는 소유자와 저장소 이름을 기본값으로 추론합니다.
브랜치 기본값은 main이므로 실제 데이터 저장 브랜치가 다르면 수정하세요.

저장 동작:
- 먼저 브라우저에 데이터와 변경분을 함께 저장합니다.
- GitHub 최신 파일을 읽습니다.
- 이 기기에서 변경한 날짜와 설정만 최신 파일에 반영합니다.
- 업로드 성공 시 해당 변경분을 비웁니다.
- 실패 시 변경분을 보존합니다.

앱 시작 시에도 원격 기록을 확인하고 미동기 변경분을 반영합니다.
토큰이 없으면 공개 원격 파일을 읽을 수는 있지만 업로드는 하지 못합니다.

동기화 재시도 버튼으로 수동 재시도할 수도 있습니다.

같은 날짜의 수입 기록 또는 트레이딩 기록은 각각 하나의 단위로 병합합니다.
같은 날짜를 여러 기기에서 동시에 수정하면 나중에 동기화한 변경이 적용됩니다.
동일한 날짜를 여러 기기에서 동시에 편집하지 않는 것을 권장합니다.

토큰은 현재 탭의 sessionStorage에만 저장합니다.
탭을 닫거나 다른 기기를 사용하면 다시 입력해야 할 수 있습니다.
JSON 백업에는 토큰을 넣지 않습니다.

공개 저장소의 기록은 공개될 수 있습니다.
공용 기기에서는 토큰을 저장하지 마세요.

원격 버전 충돌은 최신 파일을 다시 읽어 제한된 횟수만 재시도합니다.
계속 실패하면 로컬 변경분을 유지하고 상태를 표시합니다.

저장소를 변경하기 전에는 JSON 백업을 보관하세요.
새 저장소로 바꾼다고 기존 저장소의 기록을 자동 복사하지는 않습니다.

백업을 복원하면 현재 로컬 기록을 교체한 뒤 알려진 로컬 변경사항을 원격에 반영합니다.
다른 기기에서 추가한 미확인 날짜를 백업 복원으로 일괄 삭제하지는 않습니다.

## AI 거래 가져오기

트레이딩 화면에서 프롬프트를 복사합니다.
외부 AI에 프롬프트와 거래 화면을 전달하고 반환된 JSON을 붙여넣습니다.

앱이 AI 서비스를 직접 호출하지 않으며 AI API 키도 요구하지 않습니다.
날짜, USD 통화, 랏수, 손익, 거래번호 중복을 검증합니다.

검토 후 입력표에 추가해도 아직 저장된 것은 아닙니다.
거래 내용을 직접 확인하고 트레이딩 저장을 눌러야 합니다.

AI가 거래 손익을 잘못 읽을 수 있으므로 원본과 반드시 대조하세요.

## 검증 범위

계산 테스트 페이지에 다음 항목을 포함합니다.

- 배달 0원과 미입력 구분
- 트레이딩 손실과 리베이트 환산
- 주 7일 배달 시나리오
- 상세·합산 입력의 배달 합계
- 그 외 수입의 전체 회복액 반영
- 그 외 수입만 있는 날의 배달 평균 제외
- 시작일 및 완료일 포함 계산
- 목표 완료일 역산
- 남은 손실이 0인 경우
- 실제 평균의 0원 기록 포함

테스트 페이지는 브라우저에서 실행해야 합니다.
